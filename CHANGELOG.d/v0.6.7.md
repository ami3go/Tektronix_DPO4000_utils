# v0.6.7 - 2026-08-31

## Fixed

- Updated DPO4000 screen hardcopy setup to use the documented `SAVE:IMAGE:FILEFORMAT` command instead of `HARDCOPY:FORMAT`, avoiding a model-specific unsupported query/write path before `HARDCOPY START`.
- Screen capture still restores the previous image format and VISA timeout/termination settings after success or failure.
- Waveform acquisition now treats `WFMOUTPRE:NR_PT` as the authoritative number of points returned by `CURVE?`, including cases where the oscilloscope transmits fewer points than the selected `DATA:START`/`DATA:STOP` source range.
- Explicit `DATA:START` and `DATA:STOP` readback validation remains strict, and impossible outgoing counts larger than the selected source range are rejected.
- Legacy waveform/CSV methods therefore support long DPO4000 records whose outgoing waveform representation is reduced by the scope instead of failing on a false point-count equality assumption.
- Package version bumped to `0.6.7`.

## Tests

- Updated hardcopy command/restoration regression coverage for `SAVE:IMAGE:FILEFORMAT`.
- Added a hardware-derived waveform regression where the selected DATA range contains more source points than `WFMOUTPRE:NR_PT` reports for the outgoing `CURVE?` transfer.
- The follow-up real-hardware verification should specifically confirm that the `hardcopy` and `legacy-csv` cases that failed on v0.6.6 now pass.
