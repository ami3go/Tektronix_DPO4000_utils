# v0.6.11

### Planned

- Added `docs/logger-tab-plan.md` defining the sustained Logger architecture, source model, producer/writer pipeline, bounded buffering, CSV and append-only binary DPO4LOG output, file rotation, retention, reconnect behavior, profiles, run reporting, phased implementation, tests and 24/7 qualification gates.
- Added `docs/logger-tab-layout.md` defining the canonical Logger UI layout, dynamic source/mode controls, runtime health telemetry, queue visualization, rotation/retention controls, running-state locking and UI acceptance criteria.
- Logger source planning covers CH1..CH4, MATH, MEAS1..MEAS8, and BUS1..BUS4 decoded events.
- BUS decoded-event logging is explicitly gated on a new public driver API and hardware verification because the current BUS API exposes configuration/capability data but not decoded transaction extraction.
- Waveform logging is specified as repeated finite-record transfer rather than unverified zero-dead-time hardware streaming. The UI must expose effective record rate, transfer throughput, skipped/dropped records and queue pressure.
- Proposed a dependency-free versioned `.dpo4log` binary container using append-only framed records with metadata, compact raw waveform samples, checksums, partial-tail recovery and CSV conversion tooling.
- Canonical application navigation becomes `Connection -> Channels -> Measurement -> Trigger -> Acquisition -> Automation -> Logger -> File -> Display -> Log` when Logger is implemented.
- Package/planning version bumped to `0.6.11`.

No Logger runtime implementation is included in this planning increment.
