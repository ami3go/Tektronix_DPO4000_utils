# v0.6.6 - 2026-08-31

## Changed

- Added a `Keep session` checkbox to Connection options.
- When `Keep session` is enabled, one worker-thread-owned DPO4054/VISA session is opened lazily and reused across repeated operations such as Preview, acquisition controls, setup reads, BUS/REF reads, and saves.
- When `Keep session` is disabled, the established short-lived behavior is preserved: every operation opens, uses, and closes its own session.
- Changing the selected VISA resource, Ethernet host/port/protocol, or connection mode invalidates and closes any retained session so the next operation reconnects using the new definition.
- Disabling `Keep session` closes the retained session immediately, and closing the application closes it before Qt shutdown.
- Non-transport validation/protocol errors no longer discard a retained session; real transport/time-out errors invalidate it so the next operation reconnects cleanly.
- The `Keep session` setting is stored in GUI preferences and defaults to disabled for backward-compatible behavior.
- Package version bumped to `0.6.6`.

## Tests

- Added PySide6 runtime coverage proving repeated operations reuse one connection, non-transport failures preserve it, transport failures force a reconnect, and explicit close releases the retained scope.
- Added GUI preference/runtime coverage for the `Keep session` checkbox and retained the existing per-operation fallback path.
