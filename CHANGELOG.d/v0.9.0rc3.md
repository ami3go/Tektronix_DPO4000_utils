# v0.9.0rc3 — Live View fixes and speed-up (supersedes rc2)

- **Fix the Live View runtime error in rc2** (`A22 owns the instrument; Stop live
  streaming first`): the instrument-lease gateway only admitted the old single-channel
  action name, so every Live View read was rejected. The panel and gateway now share
  one action constant, with a window-level regression test.
- Live View reads each channel at the scope's own record length (the transfer-size
  selector is gone), refuses a record above 1M samples before `CURVE?`, and fails fast
  with a clear message when a selected channel is not displayed instead of timing out.
- Speed up streaming: one `WFMOUTPRE?` query replaces nine per-field queries, and
  Live View reuses the preamble (`PreambleCache`) while a fingerprint of the horizontal
  and per-channel settings is unchanged (refreshed at least every 5 s), decoding the
  sample block from raw bytes. One four-channel 100k-point group on a DPO4054 dropped
  from about 970 ms to about 720 ms over TCP/IP (about 800 ms to about 500 ms over USB).
  The public read API still re-reads the preamble every time.
- Add per-channel info cards (label, vertical resolution, sample interval/rate, record
  length/span, time/div, Vpp) and an auto/fixed vertical grid to the Live View.
- Add `scripts/run_live_view_soak.py`, an offline 12 h four-channel Live View soak with
  an offline `--validate-report` mode; fix the P0 release evaluator on Windows.
- Release workflow: tags containing `rc` are published as pre-releases, and a missing
  `docs/releases/<tag>.md` now fails the release job instead of publishing empty notes.
