# DPO4000 Desk v0.7.0

v0.7.0 is the runtime/qualification follow-up to the v0.6.72 production-hardening merge. It changes the launched GUI from synchronous short-lived scope operations to one serialized worker-owned DPO4054/VISA session with asynchronous Qt completions.

## Highlights

- **Persistent async scope runtime** — one dedicated worker thread owns the scope connection; GUI actions return immediately and finish through callbacks.
- **No nested Qt event loops** — production scope dispatch, retained sessions and A11 recovery no longer call `QEventLoop.exec()`.
- **Safe reconnect and close** — transport failures invalidate the retained scope, retries reconnect lazily, queued work can be cancelled, and application shutdown closes VISA on its owning thread before the window exits.
- **Coherent scope refresh** — IDN/Core/REF/BUS refresh stages share one connection while keeping optional-stage fault isolation.
- **Automation/Logger migration** — launched A1..A7 capture state machines and Logger record capture now finalize tokens/records only after asynchronous worker completion.
- **Driver-owned transport policy** — runtime session configuration uses public `configure_session()` instead of GUI access to raw VISA attributes.
- **BUS decoder safety** — decoded transaction extraction remains explicitly unqualified unless real hardware proves a documented command path; no undocumented decoder SCPI is invented.
- **Reproducible release builds** — `constraints-release.txt` pins release tooling/runtime dependencies and the workflows publish the actual resolved environment with build artifacts.
- **Long-duration qualification tooling** — a manual self-hosted DPO4000 hardware-soak workflow supports 24/72-hour stability evidence.

## Compatibility

- Python: 3.10–3.13 CI matrix.
- Desktop: PySide6.
- Existing `BusDecodedEvent` positional construction remains compatible.
- `scope_session()` remains available for scripts/short-lived use; the launched GUI uses the persistent worker runtime by default.
- The **Keep session** preference now defaults to enabled. Disable it only for VISA backends that require a reconnect after every operation.

## Hardware qualification status

The repository contains the public-API verifier and long-duration soak workflow. A successful hosted/unit test run does **not** constitute a DPO4054 hardware soak. A 24 h or 72 h PASS may only be claimed after the corresponding self-hosted bench workflow completes and its artifact is reviewed.

Decoded BUS transaction export remains capability-gated until that feature has its own documented command path and real-hardware qualification.

## Next milestone

v0.8.0 is reserved for replacing the historical Qt window inheritance chain with a composed `QMainWindow` + page/controller/service architecture. It is intentionally separate from this runtime rewrite to reduce migration risk.
