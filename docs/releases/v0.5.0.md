# DPO4000 Desk v0.5.0

v0.5.0 marks the first hardware-validated 0.5 release of the refactored DPO4000 Desk application and reusable Python driver.

## Highlights

- PySide6 is the sole supported desktop frontend; legacy Tk code has been removed.
- GUI scope operations go through the public `dpo4000_utils` driver API instead of issuing raw SCPI from the UI.
- Successful connection can automatically populate CH1..CH4, MATH, measurements, trigger, acquisition, display, REF, and BUS controls from the connected oscilloscope.
- REF1..REF4 waveform configuration and guarded waveform storage are supported.
- Decoded BUS controls support I2C, SPI, CAN, RS-232/UART, LIN, FlexRay, Audio, USB, and Parallel command families where supported by the instrument/options.
- Automatic optional-feature discovery uses the scope-reported `CONFIGURATION:BUSWAVEFORMS:NUMBUS?` and `CONFIGURATION:REFS:NUMREFS?` capability counts.
- On a two-BUS DPO4054, automatic refresh no longer probes BUS3/BUS4, eliminating the observed VISA timeout warnings.
- Optional REF/BUS refresh uses bounded timeouts and staged error isolation so optional features cannot block core scope state loading.
- The connection page includes a persistent **Read all parameters after connection** option.
- Windows and Linux desktop packaging is automated through GitHub Actions.

## Validation

The BUS capability-driven refresh path was validated against real DPO4054 hardware: BUS1/BUS2 were read successfully and the previous BUS3/BUS4 timeout warnings were eliminated.

The repository CI matrix covers Python 3.10, 3.11, 3.12, and 3.13 plus the PySide6 desktop runtime suite.

## Release assets

The release workflow publishes:

- Windows application ZIP
- Linux executable
- Debian package
- AppImage
- Flatpak

A VISA runtime/backend is still required on the target machine for real oscilloscope communication.
