# DPO4000 Utils v0.8.0

v0.8.0 changes the **desktop GUI architecture**, not the public oscilloscope protocol contract established in v0.7.

## Production GUI architecture

The `dpo4000-desk` entry point now launches `dpo4000_utils.gui_qt.composition.window.QtScopeWindow`.

That class directly inherits only `QMainWindow`. The historical chain of `QtScopeWindow` feature subclasses is no longer part of the production window MRO.

The shell composes explicit services/controllers for:

- persistent asynchronous scope dispatch;
- lazy page construction and page selection;
- preferences;
- application logging;
- output-folder/path handling;
- frameless titlebar/window chrome;
- lifecycle and shutdown.

Eight named `FeaturePageController` objects represent Connection, Channels, Measurement, Trigger, Acquisition, File, Display, and Log.

## Compatibility surface

The mature v0.7 widgets, Automation A1..A12, Logger stack, BUS support, preview, acquisition, measurements and settings remain available through `composition/legacy_surface.py`.

This adapter is a deliberate migration seam. It is the only v0.8 composition module allowed to import the historical `*_window` implementation. Legacy classes may continue to exist as compatibility shims, but they are not allowed back into the production launch MRO.

## Instrument runtime

The v0.7 runtime contract is unchanged:

- one retained DPO4054/VISA session is owned by a dedicated worker thread;
- scope operations complete asynchronously through Qt callbacks/signals;
- Core → REF → BUS refresh retains one connection;
- transport policy remains inside the public driver boundary;
- Automation/Logger cancellation, recovery, bounded writer behavior and reporting remain active.

All compatibility-surface `_run_action()` calls are routed through the v0.8 `ScopeDispatchController` before entering that runtime.

## Architecture CI

`tests/test_gui_qt_composition_architecture.py` prevents regressions by checking that:

- the production class directly inherits only `QMainWindow`;
- runner/package exports select the composition shell;
- only `legacy_surface.py` imports the historical window stack;
- production composition services are explicit;
- page build/navigation is routed through the page registry;
- no composition controller owns raw PyVISA/SCPI operations.

Runtime smoke tests construct the composed window offscreen and verify controller routing and existing lazy-page behavior.

## Hardware qualification

v0.8 does not change the hardware qualification policy. The v0.7 read-only/reversible/full verifier and 24 h / 72 h self-hosted DPO4054 soak tooling remain the source of physical-instrument evidence. Hosted CI does not fabricate hardware PASS results.
